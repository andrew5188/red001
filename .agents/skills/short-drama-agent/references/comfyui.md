# 本地ComfyUI工作流执行

## 环境与构建

- 在当前电脑检测ComfyUI安装目录、可用Python和实际服务地址；从用户配置、进程参数、工作区及日志核对，不继承其他电脑的绝对路径。已保存的本机路径只是线索，首次迁移必须重新验证。
- 先按render-planning.md补齐清晰度与画幅、检测硬件并配置SelfLift＋H3 latent放大。仅在制作已授权后提交生成；后台启动服务时隐藏窗口、保存日志，不终止其他任务。
- GET /system_stats检查设备与内存；GET /object_info读取实际节点schema和模型选项。必要时读取本地源码或查询原作者实现，不凭记忆拼节点。
- 默认一项目一份iworkflow/main.ui.json，main/保存对应API模板、配对校验、分段参数、共用脚本和环境信息。换场景或10秒片段只切换人物/场景/提示词/种子/输出名与连续性输入，不生成新的UI工作流。首段关闭预留引导分支，连续片段绑定前段检查通过的真实末帧。现有节点结构无法满足新生成方式时才增加模板。执行前读取用户修改并同步API，无法可靠转换时需重新导出，不能忽略UI编辑。
- 单段工作流包含模型/LoRA、文本与图片参考条件、音视频latent、采样与放大、视频/音频解码、封装及输出。验证必填输入、类型、链接、动态选项、模型与文件可用性。UI图未经前端加载检查时标明未验证。
- UI图不能直接POST /prompt。按当前schema构建API图，不假定widgets_values顺序与输入顺序一一对应。

## 提示词与参考

- 直接使用h3-prompt-writing提供的MiniMax H3官方格式，根据输入选择T2VA、I2VA、FL2VA、L2VA或Ref2VA。
- 文本/关键帧模式使用integrated_multimodal_description、overall_soundscape、non_diegetic_music。Ref2VA使用subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape、non_diegetic_music。
- 英文字段与镜头描述遵循技能，中文台词保留在正式对白标签中。每个10秒片段独立从0计时，只包含本段内容。
- 公共人物与本段场景在项目层管理，编译成本段完整提示词和稳定参考槽位。角色图三视图是一个人的多个角度，不能生成多个副本。POST /upload/image后记录name/subfolder/type并按节点真实路径解析规则引用。

## 提交前与验收门槛

- 执行 [content-review.md](content-review.md)：内容检查独立于节点、格式及媒体参数。每项目首段人工确认，首次武戏另检查首个动作试片（同一片段不重复确认）；其余自动检查并合并交付。准备/提交/合并入口检查首段确认及其输出指纹仍有效；后续音频主观检查可按该策略waived，但技术音频检查必须通过。
- 构建项目脚本时在准备与提交两个入口检查内容审查是否有效；提交入口重新读取清单并校验准备记录对应的文件指纹。仅在准备时检查不足以防止之后修改输入。失败时在POST /prompt之前退出，不写queued或伪造任务ID。
- 历史查询只更新任务运行事实；收集旧输出只增加检查证据。两者不得把已stale的素材或内容审查重新标为通过。
- 通用UI仍是可编辑模板，历史API仍供追溯；这些文件不因存在就具备提交资格。用户手动在ComfyUI直接运行会绕过Agent脚本，说明这一边界，不声称文档能阻止手动执行。

## 逐个10秒生成与连续性

- 每次提交只生成一个10秒视频，单GPU按顺序执行。POST /prompt后立刻保存prompt_id；通过GET /history/{prompt_id}、GET /queue或WebSocket /ws跟踪。提交超时先查任务，不盲目重交。
- 每段的实际API、参数、种子、任务ID、耗时、输出和检查保存到main/runs/<场次>/<片段>/<尝试>/。准备、已提交、已完成明确区分；记录是模板套用结果，不是新的可编辑工作流。前段完成检查后再准备依赖它的后段。
- 同一时空记录实际结尾站位、视线、手势、道具、衣服、光线与声音。按所用模式/节点能力传入实际末帧、尾段或latent上下文，并核实接线。末帧仅作为普通人物参考不等于固定首帧；纯文字续接不等于真实连续性条件。
- 明确跳时空按正常剪辑处理。连续动作、声音与配乐承接前段，不重复动作和台词；前段重做时重查后段依赖。
- 目标交付时长与采样帧网格分开处理。核对当前模型对齐约束；此前H3实现使用17k+5，243帧/24fps为10.125秒，不能把它当作精确10秒。设计对白尾部留量，根据实际输出同步处理音视频到每段10秒，不截断台词，不重复引导帧，不伪造时长。

## 自动合并最终成果

- 所有片段成功且通过必要检查后自动合并，无需再次询问是否拼接。以project.json中的场次/片段顺序建立明确清单，不按随意的文件名排序，也不混入试片、失败版本和历史成片。
- 确认所有预期片段真实存在、可解码，统一分辨率、帧率、像素格式、编码与音频采样率/声道；符合拼接条件时可使用FFmpeg concat，否则先统一编码。
- 确认画面衔接、无上下文重复、无黑帧/丢段，检查对白、环境声和配乐接点。必要音频淡化或混音不能意外改变画面时长、叠加对白或重复BGM。
- 默认完整成片时长为片段数×10秒；存在额外引导帧或音频封装误差时检查并处理，精确目标与实际结果记入报告。
- 输出到04_全片输出/，版本化命名；最终用ffprobe/解码检查尺寸、帧率、时长与音轨，并在工具允许时观看、试听。未完成的主观检查明确记录。
- project.json.final_output指向已验证的最终文件后才将全剧标为complete。保留分段和分场结果，但交付以一个完整视频为主。任何片段失败或合并失败都保存进度并报告，不能漏段后宣称完成。

## 有声与目录

默认包含对白、环境声、同步音效及无歌词配乐。音频解码输出必须实际连接视频封装节点；仅存在audio_vae或音轨不代表对白/配乐合格。检查同步、非预期静音、削波、台词完整和可辨程度；没有实际试听则标为未验证；首段人工确认后，后续和最终成片按策略记录主观音频豁免并自动继续，不重新要求逐段试听。

目录：00_故事大纲 / 01_完整剧本 / 02_角色库 / 03_分场制作 / 04_全片输出 / iworkflow。分场目录保存场景、提示词、分段视频与检查；iworkflow集中保存可编辑工作流与提交快照。所有产物版本化，保留用户文件，不在文件名或快照里存储凭据。
