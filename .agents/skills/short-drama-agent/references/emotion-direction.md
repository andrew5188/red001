# 场景情绪与人物表演策略

本策略用于剧本、每段H3 Prompt、提交前检查和成片验收。情绪目标不是只写在摘要里的形容词，也不是要求模型保证一次成功。通过可见表演和有依据的检查提高一致性，偏离时定向重试。

## 生成前：先定场景，再定人物

在完整剧本中为每场保存情绪表，项目清单 `scenes[].performance_plan` 保存可执行摘要，不额外散建情绪文件。

- 场景层：主情绪、剧情触发原因、进入状态、转折和离开状态；强度按本场题材设定，不把所有故事写成甜蜜/微笑。
- 人物层：各自当下想要什么、对对方行为的理解和反应。双方可处于不同情绪，例如一个惊喜、另一个克制欣赏；避免同步做同一种表情。
- 片段层：`groups[].performance_plan` 记录 `entry`、`trigger`、`change`、`exit`、`actors`、`camera`、`acceptance`。每10秒通常只安排一个主要转变和一到两个清楚的反应，允许情绪保持，不为凑变化机械变脸。
- 用“触发事件→短暂停顿/反应→外在表现→留下的状态”组织表演。外在表现选少量眉眼、嘴角、视线、呼吸节奏、肩颈或手势线索，不堆砌全部肌肉指令。
- 表情须与身份、情境和强度相符。克制不等于全程面无表情；丰富也不等于持续大笑、张嘴、频繁眨眼或夸张摇头。

## 写入官方H3 Prompt

- 不给H3擅自增加自创顶层字段。把情绪原因和可见表演编入官方 `detailed_description`（基础模式为 `integrated_multimodal_description`）的对应时间段；声音语气遵循官方声音字段规则。
- 写清哪个角色、被什么触发、看向哪里、表情如何变化、变化先后和结尾保持；不能只写“开心、悲伤、氛围感”。
- 对白留出起势、说话、反应和停顿。说话时优先嘴型和语气，减少同时发生的复杂动作；听者也有与台词因果相符的反应。
- 镜头必须让表演看得见：关键情绪优先稳定中近景或必要反应镜头，避免背脸、遮挡、远景或快速镜头运动盖住表情；不为了表情牺牲用户要求的场景元素。
- 连续段先查看真实尾帧，继承视线、手势和表情强度，再过渡到目标情绪。不能每段重新从中性表情开始，不能重复已经完成的惊讶/抬头/微笑动作。

## 提交和输出检查

- 输入检查单独记录 `performance`：剧本情绪表、角色表演、逐段Prompt和实际API是否一致，关键表演是否处于能看见的构图，是否能在10秒内完成。性能计划纳入输入指纹；结构完整不等于语义检查通过。
- 输出按关键情绪节拍查看实际帧/片段，记录时间码和观察。分别判断“情绪方向是否读得出”“变化是否自然”“对方是否有合理反应”“与上一段是否衔接”。不要把某个肌肉变化或精确表情角度机械当作唯一合格标准。
- 重要情绪反向、全程僵硬且叙事反应缺失、明显突然变脸、关键表情被遮挡时判失败。先减少同时动作、明确视线和触发原因、调整构图或时序，再在现有重试预算内重做受影响片段；不直接增加更多情绪形容词或随机换种子无限重试。
- 表演可读、叙事成立但某个微表情未完全实现时记录偏差，不为追求不可控的细节无限重做。声音无法主观检查时按首段人工确认策略记录未验证，不冒充已听出情感语气。
- 人工确认仅在项目第一个视频和首次武戏试片设置（同一片段不重复）；后续情绪与表演由Agent检查，不增加逐场/逐段审批。已有成片不因技能更新自动重做；将新策略用于待制作部分，回溯重做须符合用户范围。
