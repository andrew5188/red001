# 角色素材与独立目录

创建角色、补充素材、选择视频参考时使用。每个角色有稳定角色ID及独立目录：`02_角色库/<角色ID>_<角色名>/`。同一人的换装、佩剑等版本归入同一角色目录，不另建角色身份。姓名变更以ID维持关联；文件名保留版本，不覆盖已用文件。

## 固定素材组合

每个需要独立身份的角色在进入视频制作前准备并实际检查以下三类素材：

- `三视图_v1.png`：纯白底，正面、背面、90度侧面等比例完整全身。用于核对脸型、发型、衣服轮廓和道具位置。
- `单人全身_v1.png`：纯白底，画面仅一个人，完整头脚，正面或轻微三分之四视角，双手姿态自然可辨。用于全景、走动、站位和武戏。
- `单人半身_v1.png`：纯白底，画面仅一个人，头顶到腰/胯部，完整保留发饰和肩部，脸部细节清晰，表情自然中性或轻柔，避免过强情绪。用于对白、情绪和中近景；手进入构图时不切断关键手势。

“照片”指角色参考图，仍保持选定的半写实国风。先确认同一造型源，再基于它派生全身和半身图；遵循imagegen技能，不三次独立选角。三类图年龄、五官、头发、发饰、服装颜色、腰带与佩剑位置一致。图像派生不保证身份绝对不变，必须实际查看确认。换装/佩剑版本命名如`单人全身_佩剑_v2.png`，保持版本间关系。临时路人按出镜计划配置，只有需要稳定身份的龙套建立同样角色库。

## 视频参考选择

按镜头选择主参考：全景/动作/脚步选单人全身；对白/情绪/中近景选单人半身；具体开场构图可以使用已检查的角色场景合成首帧，保存在对应分场目录。每名角色默认只给当前片段一张合适的人物参考，不能把三视图、全身和半身全部传入以为会更稳定。三视图默认供造型核对，避免多角度排版被解释为多个角色。确有必要多参考时明确同一身份映射并检查人数。

源图为半身不代表禁止身体出镜，但全身动作应选择能提供完整比例和服装的图。半身图不预设整剧持续微笑；每场情绪由performance_plan和Prompt控制。只传当前镜头允许的人物，画外人物不加入人物参考。实际API、上传文件、Prompt标签、人数计划一致后才提交。

## 登记与迁移

`characters[].asset_directory`记录目录，`characters[].assets`分别登记three_view/full_body/half_body的path、status、版本、造型/父源、检查证据和SHA256。通过检查后才标complete；缺图是pending，不能把既有角色status=complete当作新增半身图已存在。逐段清单记录实际选择的图片，不只记录文件夹。

新项目和新建角色使用独立目录。旧项目已有文件按已登记有效路径继续复用；补充新素材放角色目录。用户要求迁移已有文件时先检查引用并更新清单/参数/必要草稿，验证文件哈希一致；历史执行快照保留原路径和实际执行证据，不伪造迁移前历史。不能因改目录自动重渲染已完成片段。规则更新不新增人工确认，首段和首次武戏沿用原规定。

## 场景资产采用同样的独立目录

场景库与角色库并列，按稳定地点ID保存：`02_场景库/<场景ID>_<地点名>/`。例如`SC02_亭侧雪廊/母图_v1.png`、`主机位_v1.png`、`反打_v1.png`、`侧面_v1.png`、`局部_廊柱_v1.png`。只生成实际镜头需要的视角，不为凑齐目录强行生成所有角度。

场景ID代表地点，场次ID代表剧情顺序；多个场次发生在同一地点时共用同一场景目录，各场各段引用所需视角。不要为每场复制一套背景，也不按每个视角新建地点身份。不同天气/时段/破损状态通过清晰的状态名和版本区分，并记录关联，如`主机位_夜雪_v2.png`。

先制作和核对无人母图，再基于同一母图派生所需角度，检查建筑材质、柱栏布局、出入口、地形、光线和天气是否一致；需要空间匹配时记录关键地标与机位方向，不把独立生成的相似建筑声称为同一空间的精确重建。场景参考保持无人，避免路人、肢体或未安排人形倒影。为具体分场合成的人物入景首帧属于分场素材，存`03_分场制作/<场次>/`并引用其人物和场景来源，不混入无人场景库。

项目清单以locations或等效场景库登记地点ID、asset_directory、master、views和state；各视角保存path、source、status、SHA256及检查依据。scenes[].location_id与逐段参考绑定引用同一地点，选择视角时与Prompt机位和前后衔接一致。既有有效路径可复用；新场景及后续新角度使用独立目录，用户要求迁移旧素材时同步检查引用和历史证据，不能仅移动文件造成断链。

## 同性角色的辨识度检查

为同性主要角色先建立差异化选角，再生成角色素材；不能只换姓名、衣服颜色或发饰而沿用同一张脸。固定半写实国风是共同画风，不是共同五官。角色性别本身不规定长相；所有可能混淆的角色也按同样方法检查。

每个角色在characters[].visual_identity记录具体可见的脸型/下颌、眉眼形态、鼻口特征、发型轮廓、身形比例与服装剪影。年龄感按已确认年龄呈现，不靠单写“18岁”“30岁”或给一人微笑、一人皱眉制造差异。优先至少两项稳定面部差异，再配合至少一项发型或体态轮廓差异；这是制作检查项，不是相似度数值保证。不擅自用伤疤、残疾、民族特征或夸张丑化强行区分。

角色图完成后，把可能混淆的同性角色在相近视角、大小、光照、中性表情下并排查看，分别检查半身脸部和全身剪影：遮去名字、不依赖衣服颜色，能否认出是谁；并检查每人三类图内部仍是同一身份。在character_distinction_review登记比较的角色ID、实际图路径/SHA256、稳定差异、证据和passed/failed/pending。只写差异描述、换颜色或重新命名不算通过。未看实图不得标passed。

相似到容易混淆时，先修正尚未固定或尚未进入有效成片的角色，保留已经确定的主角；从修正后的身份源重新派生该角色的三视图、全身和半身，不让三张各自选角。同步检查含该角色的入景关键帧、Prompt身份描述与参考映射。相关视频输入在辨识度复核前不得提交。保留旧版本，按依赖标stale；不因通用规则更新自动重做已验收成片。

用户指出角色过于相似时，记录原话、角色ID和影响范围，将相关辨识度检查标failed，并拦截未提交的受影响片段；不能用此前单角色“身份一致”检查覆盖这条反馈。明确只要求更新规则时先落地规则与问题登记，不把它扩大为立即重绘或整剧重渲染。后续制作按已授权范围先解决问题，沿用项目原有人工关卡。
